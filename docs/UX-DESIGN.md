# UX Design — IT Asset Management System

อิงตาม `docs/STRUCTURE.md` และโครงสร้างหน้าเว็บ/API ปัจจุบัน เน้นหน้าจอใช้งานง่ายบนเดสก์ท็อปและมือถือ พร้อม visual theme ขาว–เขียว (`#74B728`) ที่ผู้ใช้เลือก

## แนวทางภาพรวม

- **ภาพลักษณ์:** พื้นหลังเทาอมเขียวอ่อน, พื้นผิวการ์ดสีขาว, สีเน้นเขียว `#74B728`, ตัวอักษรสีเข้ม และสีสถานะเฉพาะความหมาย
- **โครงหน้า:** แถบบนสีขาวติดด้านบน แสดงชื่อระบบ เมนูหลัก และบัญชีผู้ใช้; เนื้อหากว้างสูงสุด 1,240px
- **ตัวอักษรและพื้นที่:** Segoe UI / Noto Sans Thai, หัวข้อชัดเจน, ช่องกรอกสูงอย่างน้อย 40px และปุ่มมีพื้นที่คลิกเหมาะกับมือถือ
- **Feedback:** ใช้ข้อความ inline สำหรับข้อผิดพลาดของฟอร์ม, Toast สำหรับผลสำเร็จ, confirmation dialog สำหรับรายการที่ย้อนกลับไม่ได้
- **Responsive:** ตารางเลื่อนแนวนอนเมื่อจอแคบ, การ์ดสรุปเรียงตามความกว้าง, ปุ่มและตัวกรองขึ้นบรรทัดใหม่ได้

## Sitemap และสถานะ

| เมนู | ระยะ | จุดประสงค์ / องค์ประกอบ |

## หน้าจออุปกรณ์

1. หัวหน้า: breadcrumb/ชื่อหน้า, คำอธิบายสั้น และปุ่ม “เพิ่มอุปกรณ์”
2. KPI สี่การ์ดพร้อมตัวเลขใหญ่และสีขอบตามสถานะ
3. กราฟหมวดหมู่และคำอธิบายสี; ให้มี empty state เมื่อยังไม่มีข้อมูล
4. แถบค้นหาและตัวกรองหมวดหมู่/สถานะ วางก่อนตาราง
5. ตาราง Asset ID, ชื่อ, หมวด, ผู้ถือ, สถานะ และ Actions; บนมือถือคง scroll แนวนอน
6. Actions ใช้ปุ่มคำและ icon พร้อม tooltip; ซ่อนตาม permission และซ่อน action ที่สถานะไม่อนุญาต
7. แบ่งหน้า 10 รายการต่อหน้า; แสดงจำนวนผลลัพธ์และปุ่มก่อน/ถัดไป

## Flow สำคัญ

### เพิ่ม/แก้ไขอุปกรณ์
กรอก Asset ID และชื่อเป็น required → แสดง error ใต้ช่อง → disable ปุ่มบันทึกจนข้อมูลจำเป็นครบ → เมื่อบันทึกสำเร็จปิด modal, Toast, กลับ focus ไปยังรายการ

### จ่ายอุปกรณ์
กด “จ่าย” จากแถวที่ Available → modal แสดงชื่อและรหัสอุปกรณ์ → เลือกพนักงานจากรายการ (ไม่ให้พิมพ์เป็นชื่ออิสระ) → วันครบกำหนด/สภาพก่อนจ่าย → ยืนยัน → โหลดข้อมูลและประกาศผลด้วย Toast

### รับคืน
กด “รับคืน” จากแถว In Use → สรุปผู้ถือและอุปกรณ์ → เลือกสภาพหลังคืน → checkbox “ต้องส่งซ่อม” เปิดช่องหมายเหตุ → ยืนยัน → ถ้าชำรุดให้เห็นสถานะ Maintenance ทันที

### เลิกใช้อุปกรณ์
ใช้คำว่า “เลิกใช้งาน” แทน “ลบ” → เลือกเหตุผลและยืนยัน → เปลี่ยนเป็น Retired แต่ยังค้นประวัติได้

## สถานะหน้าจอ

- **Loading:** skeleton สำหรับ KPI/ตาราง และป้องกันกด action ซ้ำ
- **Empty:** อธิบายว่าไม่พบข้อมูล พร้อม CTA ที่เหมาะ เช่น เพิ่มอุปกรณ์ หรือ ล้างตัวกรอง
- **Error:** แสดงข้อผิดพลาดใกล้บริเวณที่เกี่ยวข้อง พร้อมปุ่มลองใหม่
- **Conflict (409):** แจ้งว่าข้อมูลถูกเปลี่ยนแล้ว มีปุ่มโหลดข้อมูลล่าสุด
- **Unauthorized (401):** แจ้ง session หมดอายุและกลับหน้า Login
- **No permission (403):** แสดงข้อความไม่มีสิทธิ์ โดยไม่แสดงปุ่มที่ใช้ไม่ได้

## สถานะสี

| สถานะ | สี | การใช้งาน |
|---|---|---|
| Available | เขียวเข้มบนพื้นเขียวอ่อน | พร้อมจ่าย |
| In Use | ส้มบนพื้นส้มอ่อน | กำลังมีผู้ถือครอง |
| Maintenance | เหลืองเข้มบนพื้นเหลืองอ่อน | อยู่ระหว่างซ่อม |
| Retired | เทาบนพื้นเทาอ่อน | เลิกใช้และดูได้อย่างเดียว |
| Primary action | `#74B728` | ปุ่มหลัก, tab ที่เลือก, focus ring, logo accent |
| Error | แดง | validation และเหตุการณ์ผิดพลาด |

## ความต่างจากระบบจริงที่ต้องทำเป็นงานแยก

หน้าเว็บปัจจุบันยังมีเมนูอุปกรณ์/ข้อมูลหลัก และบางข้อมูลยังมาจาก localStorage ตาม STRUCTURE.md; หน้า Maintenance, Users, Audit และ Reports ต้องเชื่อม API/พัฒนาเพิ่มก่อนใช้งานจริง เอกสารนี้กำหนด UX เป้าหมาย ไม่ได้เพิ่ม backend หรือเปลี่ยน business rules
